# فرانت کانون کارشناسان رسمی دادگستری مازندران

این پوشه را با نام front کنار backend2 قرار دهید. پروژه Next.js 16.3.8، React 19.3 و TypeScript دارد و از APIهای واقعی لاراول استفاده می‌کند. داده جایگزین یا ورود ساختگی در فرانت وجود ندارد. Node.js 22 یا 24 مناسب است؛ بررسی اجرا با Node.js 24 انجام شده است.

## اجرا

در پوشه backend2 پروژه لاراول را اجرا کنید:

    php artisan serve --host=localhost --port=8000

در ترمینال دیگر، داخل front:

    npm ci
    cp .env.example .env.local
    npm run dev

سایت: http://localhost:3000

ورود روابط عمومی: http://localhost:3000/admin/login

داشبورد: http://localhost:3000/admin

هر دو برنامه را روی localhost اجرا کنید. 127.0.0.1 و localhost را در نشانی مرورگر و API با هم ترکیب نکنید. MySQL در env بک‌اند همچنان می‌تواند DB_HOST=127.0.0.1 داشته باشد.

مقادیر .env.local:

    API_URL=http://localhost:8000
    NEXT_PUBLIC_API_URL=http://localhost:8000
    SITE_URL=http://localhost:3000

API_URL نشانی ارتباط سرور Next.js با لاراول است. NEXT_PUBLIC_API_URL نشانی API قابل دسترس در مرورگر است و نباید شامل کلید یا رمز باشد.

در .env بک‌اند:

    APP_URL=http://localhost:8000
    FRONTEND_URL=http://localhost:3000
    CORS_ALLOWED_ORIGINS=http://localhost:3000
    SANCTUM_STATEFUL_DOMAINS=localhost:3000,localhost:8000
    SESSION_DOMAIN=
    SESSION_SECURE_COOKIE=false

پس از تغییر env بک‌اند:

    php artisan optimize:clear

دیتابیس MySQL با نام kkr در backend2 تنظیم می‌شود. فرانت به دیتابیس وصل نمی‌شود.

## حساب‌های نمونه

این حساب‌ها فقط پس از اجرای سیدر در محیط local وجود دارند:

| نقش         | ایمیل                  | رمز              |
| ----------- | ---------------------- | ---------------- |
| مدیر ارشد   | admin@example.test     | DemoAdmin!2026   |
| روابط عمومی | relations@example.test | DemoManager!2026 |
| نویسنده     | editor@example.test    | DemoEditor!2026  |

فقط مدیر ارشد کاربران داشبورد را ایجاد یا غیرفعال می‌کند. نویسنده مطالب خودش را در وضعیت پیش‌نویس یا بررسی مدیریت می‌کند. انتشار و مدیریت بخش‌های سایت برای مدیر و روابط عمومی است.

ورود بالای سایت صرفاً به https://my.kkrm.ir/login/new-login می‌رود. ثبت‌نام عمومی در فرانت یا بک‌اند وجود ندارد.

## صفحات و مدیریت

- اخبار، اطلاعیه‌ها، مصوبات، آموزش، رفاه، تسلیت، رویدادهای گروه‌ها و مقاله‌ها با آرشیو، جزئیات، فیلتر و صفحه‌بندی
- اسناد، قوانین، آیین‌نامه‌ها، نظام‌نامه‌ها، فرم‌ها، صلاحیت‌ها و فایل‌های پیوست
- تاریخچه، ارکان کانون، دوره‌های هیئت مدیره، گروه‌ها و رشته‌های کارشناسی
- جستجوی کارشناسان با نام، شماره پروانه، شهر، حوزه، گروه و رشته
- قراردادها، رویدادها، حساب‌ها، سامانه‌ها، پیوندهای مفید، پرسش‌های متداول و تماس
- گالری عکس و ویدئو، نمای شبکه‌ای و بزرگ، نمایشگر با کیبورد، بزرگ‌نمایی و فایل اصلی
- داشبورد برای مدیریت تمام منابع API، ویرایشگر متن، کتابخانه رسانه، ترتیب تصاویر آلبوم، سطل زباله، بازیابی، پیام‌ها، تنظیمات و گزارش فعالیت‌ها
- مدیریت کاربران برای مدیر ارشد، بازیابی رمز و تغییر رمز

آیکون جستجو فقط اخبار، اطلاعیه‌ها و مصوبات را از GET /api/v1/search جستجو می‌کند.

محاسبه آنلاین اصلی طبق بررسی ثبت‌شده در بک‌اند ۴۰۴ بوده و از منوی عمومی حذف شده است. API و مدیریت ضرایب تعرفه در بک‌اند باقی است. سایر صفحات با خطای موقت دریافت، به‌عنوان ۴۰۴ فرض نشده‌اند. داده اسناد حقوقی، حساب‌ها و تعرفه‌های سیدر نمونه‌اند و باید پیش از انتشار با اطلاعات تأییدشده جایگزین شوند.

## امنیت و استقرار

نشست لاراول در کوکی HttpOnly می‌ماند. توکن ورود در localStorage ذخیره نمی‌شود. درخواست‌های نوشتن با CSRF انجام می‌شوند؛ خطای 419 یک بار نشست CSRF را تازه می‌کند. داشبورد روی سرور Next.js هویت را از auth/me بررسی می‌کند و API لاراول مجوز نهایی را اعمال می‌کند. داده خصوصی cache نمی‌شود. نمایش HTML پاک‌سازی می‌شود و نشانی‌های مقصد فقط مسیر داخلی یا HTTP/HTTPS هستند.

در سرور واقعی از HTTPS و دامنه اصلی مشترک برای front و API استفاده کنید. SESSION_DOMAIN، CORS_ALLOWED_ORIGINS، SANCTUM_STATEFUL_DOMAINS و SITE_URL را دقیق تنظیم کنید. SESSION_SECURE_COOKIE=true باشد. حساب‌های نمونه را استفاده نکنید. بازیابی ایمیل به تنظیمات ایمیل و اجرای worker لاراول نیاز دارد:

    php artisan queue:work

برای اجرای فرانت در حالت تولید:

    npm run build
    npm start

بررسی‌های کد:

    npm run lint
    npm run typecheck

پروژه فایل تست، پوشه tests یا وابستگی اجرای تست ندارد.

## فایل‌ها

src/app مسیرهای App Router را دارد. src/components اجزای عمومی و داشبورد است. src/lib/api-server.ts درخواست‌های سرور و src/lib/api-client.ts درخواست‌های مرورگر را انجام می‌دهند. تعریف فرم‌ها در src/lib/admin-resources.ts و مسیرهای عمومی در src/lib/public-resources.ts است. تصاویر و فونت‌های UI اصلی در public/assets قرار دارند.

راهنمای Next.js: https://nextjs.org/docs/app/getting-started/installation

مرجع امکانات: https://kkrm.ir/

## اصلاح migration بک‌اند

همراه این فرانت از بک‌اند اصلاح‌شده استفاده کنید. علاوه بر نوع ستون‌های رویداد، خروجی تاریخ‌ها در ContentPresenter استاندارد شده تا پس از کش شدن نیز به‌صورت رشته ISO برگردد. پس از جایگزینی فایل‌های بک‌اند، php artisan optimize:clear را اجرا کنید.

اگر backend2 قبلاً نصب شده است، دو فایل زیر را از آرشیو بک‌اند اصلاح‌شده جایگزین کنید و تنظیمات فعلی .env را نگه دارید:

- app/Services/ContentPresenter.php
- database/migrations/2026_10_01_000000_create_kkrm_schema.php

در database/migrations/2026_10_01_000000_create_kkrm_schema.php برای جدول events، starts_at و ends_at باید dateTime باشند:

    $table->dateTime('starts_at');
    $table->dateTime('ends_at');

نسخه اصلاح‌شده بک‌اند این تغییر را دارد. اگر اجرای قبلی نیمه‌کاره مانده و kkr فقط مربوط به نصب تازه و فاقد داده مهم است:

    php artisan migrate:fresh --seed

این دستور همه جدول‌ها و داده‌های kkr را حذف و دوباره ایجاد می‌کند. برای دیتابیس حاوی اطلاعات مهم اجرا نکنید. برای نصب کاملاً خالی:

    php artisan migrate --seed
